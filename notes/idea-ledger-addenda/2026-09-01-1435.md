- benefit: prevents logically independent converted objects from sharing a lazy asset-manifest backing identity and corrupting each other's assets
- conflict/risk: hydration increases temporary memory/IO and descriptor sharing can be legitimate elsewhere; apply only where semantic ownership must detach
- validation need: conversion regression must prove source manifest remains unchanged after editing converted object's assets; verify error/re-entry behavior for async hydration
- follow-up: preserve this ownership invariant when adding lazy/externalized storage to new domains or adding duplicate/convert/export-for-edit workflows

### Deduplication note

This is related to lazy asset manifests and externalized storage, but it is not the same underlying idea as storage externalization itself. The durable lesson is specifically the ownership-transfer rule at copy/conversion boundaries: backing-store descriptors must not be copied into an independently owned object unless shared ownership is intentional.
