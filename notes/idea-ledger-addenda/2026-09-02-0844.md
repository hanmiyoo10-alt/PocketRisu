- Source evidence: `PocketRisu/PocketRisu@9ff600a2c754d9aa203da65e9e3b84c2ceadf3e7`.
- Benefit: prevents one embedding-cache consumer from corrupting another consumer's metadata through a shared object reference. The demonstrated failure cleared parent-summary metadata and later crashed similarity search; detaching the wrapper on cache hit restores request-local metadata ownership.
- Conflict/risk: do not turn this into unconditional deep copies of large vectors. Shared immutable vector payloads are fine; caller-specific wrapper fields such as `id` and `metadata` must not be written back into the shared cache object.
- Validation need: seed one cached embedding, consume it with metadata and then with no metadata using the same cache key, and verify the first consumer's metadata remains intact and downstream similarity lookup succeeds. Verify hit/miss result contracts remain equivalent.
- Follow-up: preserve copy-on-consume or explicit immutability for shared vector-cache entries. No implementation branch/PR: already adopted in official PocketRisu.
