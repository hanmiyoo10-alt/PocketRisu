## SHARED-VECTOR-CACHE-RESULTS-ARE-IMMUTABLE

- System impact: `NO_SYSTEM_UPDATE`
- Importance: `HIGH`
- Difficulty: `LOW`

- Evidence: `HIGH`

- Source evidence: `PocketRisu/PocketRisu@9ff600a2c754d9aa203da65e9e3b84c2ceadf3e7`. `HypaProcessorV2` had mutated `metadata` directly on a shared cache object; a metadata-less query reusing the same cache key could clobber parent-summary metadata and crash similarity search. Current `develop` keeps the adopted fix by constructing a caller-owned `{ ...cached, id, metadata }` result before local insertion.
- Benefit: prevents demonstrated cross-query metadata corruption/crash without giving up vector-cache reuse.
- Conflict/risk: do not turn this into unconditional deep cloning of vector payloads; preserve bounded copy-on-read ownership unless nested cached fields become mutable.
- Validation need: exercise two logical consumers sharing one cached embedding with different/absent metadata and assert cache identity reuse cannot mutate the first consumer's local metadata; verify parent-summary lookup remains valid.
- Follow-up: preserve as a cache-ownership invariant in Hypa refactors and audit other shared-object caches before adding caller-specific fields.

### Deduplication

This is not the same underlying idea as bounded embedding request coalescing/cache eviction or narrative-memory source grounding. Those govern cache lifetime/request scope and evidence selection; this item governs object-mutation ownership after a cache hit.

### Autonomous progression

Historical evidence was inspected and confirmed against current `develop`. Because the invariant is already adopted in official PocketRisu, no implementation branch or PR was created. A helper-repository invariant dossier is recorded separately.
