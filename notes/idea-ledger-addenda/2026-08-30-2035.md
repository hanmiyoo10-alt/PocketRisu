The request path resolves the actual wire model id once before dispatch and uses it for request logging and returned generation metadata. Personal fork `hanmiyoo10-alt/PocketRisu:develop` currently preserves the same behavior in `src/ts/process/request/request.ts`.
- Benefit: request history and generation diagnostics identify the model actually used on the wire rather than a mutable preset display name or incomplete snapshot field.
- Conflict/risk: avoid broadening observability into credentials, prompt contents, or secrets; if model resolution fails, retain an identifying fallback for the failed log row rather than losing observability entirely.
- Validation need: regression coverage for renamed presets, user-value model ids, and broken model configuration; assert the request log/result metadata capture the resolved wire identity consistently.
- Follow-up: preserve during preset/request refactors. Already adopted, so no implementation branch or PR is needed.

Deduplication note: this is distinct from generation/request execution identity. `generationId` answers which request instance ran; `wireModel` answers which model identity that request actually used.
