- benefit: keeps logical copy/conversion operations independent when lazy asset manifests externalize storage; prevents converted copies from rewriting the source owner's assets.
- conflict/risk: hydration adds async/failure semantics and may be expensive for large asset lists; implementation must not mutate the source or publish a destination after failed detach.
- validation need: verify independent manifest/storage identity after conversion or clone; edits to source/destination must not cross-propagate; hydration failure must fail closed; re-entry must not create duplicate partial entities.
- follow-up: preserve as an invariant for future lazy/externalized domains and audit copy-like paths whenever descriptor-backed storage expands.

### Evidence / rationale

In `dd718991`, character↔module conversion had copied the lazy asset manifest descriptor itself. Until the next reload, the source and converted object therefore shared the same persistence owner, so editing the new object's assets could rewrite the original. PocketRisu fixed this by hydrating to a plain array copy before conversion, stripping the manifest descriptor from the detached representation, and guarding the now-async conversion UI against re-entry/failure.

### Deduplication

Kept distinct from `PLUGIN-HANDED-OUT-VIEW-WRITEBACK-AUTHORITY`: that invariant controls writeback authority for an existing owner, while this one controls ownership detachment when a new independent entity is created.

### Progression

Already adopted in official PocketRisu. Durable backfill and helper invariant dossier created; no feature branch, production change, test run, or personal PR was needed.
