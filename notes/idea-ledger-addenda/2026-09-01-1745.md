## SHARED-CACHE-COPY-BEFORE-CONSUMER-MUTATION

- System impact: `NO_SYSTEM_UPDATE`
- Importance: `HIGH`
- Difficulty: `LOW`
- Size: `XS`
- Evidence: `HIGH`
- Risk: `MEDIUM`
- Dependencies: `NONE`

- lifecycle status: `ADOPTED`
- source evidence: official `PocketRisu/PocketRisu` commit `9ff600a2c754d9aa203da65e9e3b84c2ceadf3e7`
- benefit: prevents one cache consumer's request-local metadata from corrupting another consumer that received the same shared object reference; avoids Hypa similarity crashes while retaining cache reuse
- conflict/risk: do not deep-clone large embedding arrays unnecessarily; the safe boundary is to detach only the object fields that a consumer will mutate, while preserving intentionally immutable/shared payloads
- validation need: same cache key consumed with distinct metadata/no-metadata paths; cached source object must remain unchanged; processor-local metadata must remain stable; normal hit/miss semantics unchanged
- follow-up: preserve this invariant in future cache refactors; implementation already adopted upstream, so no autonomous code branch/PR is needed

Deduplication note: this is related to cache ownership generally but is not the same underlying idea as bounded cache eviction, in-flight request deduplication, or lazy-manifest write provenance. The distinctive failure mode is mutation through a shared cached object reference, so it is preserved as a separate adopted invariant.
