- Expected PocketRisu benefit: preserve snapshot relational integrity on fresh installs/imports and prevent companion metadata from outliving or preceding the payload it describes.
- Main conflict/risk: snapshot implementations that treat a missing source as an empty successful copy can create half-published backup state; future companion domains must not publish independently of the snapshot payload identity.

### Evidence / rationale

Official PocketRisu commit `a838a957` observed a concrete bug: during first backup import, no database existed yet. The low-level copy skipped the missing payload, but plugin-storage snapshot metadata was still written. The fix gates snapshot publication on authoritative source existence and changes tests to assert the durable relationship rather than a timing-sensitive exact count.

### Deduplication

Kept separate from `BACKUP-AUTHORITATIVE-STORE-DURABILITY-BARRIER`: that idea asks whether dirty authoritative stores are durably flushed before an export/backup. This invariant asks whether a snapshot identity may be published at all when its primary payload does not exist. They protect different failure boundaries.
