## Meaningful findings

### CHAT-READING-POSITION-ANCHOR-RESTORE

RisuBard adds a logical chat scroll anchor instead of relying on raw `scrollTop`. `captureChatScrollAnchor()` records the top-visible `[data-chat-index]`, relative offset, context key, message count, and whether the reader is at the latest message. `restoreChatScrollAnchor()` corrects only the chat container after layout drift and refuses restoration when the context changed, the anchor disappeared, the position is already stable, or a new reply was appended while the reader was at latest. Integration observes bounded child-list/media-load changes, retries corrections while layout settles, captures on user scroll, and cancels stale correction after direct user interaction. Targeted Vitest coverage fixes these invariants.

This is not the same idea as `PROGRAMMATIC-SCROLL-ORIGIN`: that dossier arbitrates whether automatic scrolling may own the viewport; this idea preserves an already user-owned reading position after asynchronous layout movement. They must interoperate, not be collapsed into one owner.

Classification and progression are recorded in `notes/idea-ledger-addenda/2026-08-31-0442-risubard.md` and the helper design dossier.

### Existing bounded retry/fallback idea — evidence merge

The same commit strengthens the existing bounded request retry idea: thrown network failures, internal timeout-style aborts, and reset/socket-style transport failures are classified for the shared bounded retry loop, while an explicit user abort remains non-retryable. The source also constrains the safe thrown-transport retry path when tools are absent, avoiding accidental replay of tool-bearing requests. This is merged as source evidence into the existing retry/fallback idea rather than creating a duplicate feature.

No autonomous implementation was started from this evidence alone; PocketRisu request ownership and provider/cancel semantics still need a focused current-base audit before changing behavior.
