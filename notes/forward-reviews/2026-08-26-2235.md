## Evidence merged into existing ideas

The same RisuVault v0.3.1 range provides strong additional evidence for existing ledger ideas and should be merged rather than duplicated:

- **Active-chat paging / compaction:** `0b226cbe`, `6e2041e9`, `586226fb`, `1edcdb77`, `56990ccf`, `2846c914` — selected-chat window hydration, bounded hydrated-chat LRU, stable message DOM anchors, stale-anchor cancellation and teardown by chat identity. - **Streaming render batching:** `98fd44d1` — batches streaming display frames. Merge as evidence into long-chat/render-window performance work; do not create a standalone duplicate until PocketRisu profiling identifies streaming render as an independent bottleneck.
- **Character/media virtualization:** `21a67e82`, `86572f84`, `b4687147`, `ef09d14b`, `b3723bff` — virtualized character list, thumbnail cache/revalidation/fingerprints and focus preservation. Merge into existing thumbnail/preload optimization and bounded-list ideas.
- **Metadata-first startup / deferred hydration:** `b4f31940`, `0b226cbe`, `7ee40b3a`, `04ce44e2` — metadata bootstrap, selected-window hydration and deferred noncritical Node initialization. Merge into existing startup/deferred-domain hydration design; RisuVault patch notes explicitly state startup loads metadata before full chat bodies.
- **Dirty-scope / row-level persistence:** `2615b112`, `b67da155`, `272504f9`, `97907d98` and follow-up fixes — coalesced dirty registry and row-scoped commits. Merge as evidence into the existing domain-specific stores / explicit dirty marking / serialized commits architecture item, not as authority to replace PocketRisu's current save path.
- **Large import streaming / disk staging / atomic publish:** `dc5499c9`, `4f8caf13`, `74e9aa00`, `175d372d`, `6125e7d0`, `ed0480cf`, `1ee641b1` plus hardening follow-ups — merge into existing stream-large-payloads/import-safety ideas. Preserve staging cleanup, hard byte limits, and atomic replacement as invariants; do not port RisuVault storage architecture wholesale.
