## Meaningful transferable idea

### REAL-BROWSER-CRITICAL-FLOW-REGRESSION-HARNESS

Haejeok now exercises browser-owned behaviors in Chromium rather than relying only on unit-level logic. The useful pattern is not Playwright itself; it is keeping a small real-browser contract suite for boundaries whose correctness depends on DOM/browser/service-worker/download behavior.

Direct evidence in this range:

- first-run / welcome path is driven through the rendered UI in a real browser;
- a character export → browser download → import round-trip is exercised end to end;
- `e2e-swprobe.mjs` verifies service-worker control and interception, reproduces the streamed-download `MessageChannel` handshake, then tests the actual anchor-download path and inspects the downloaded bytes;
- the Playwright config starts a fresh application server in CI while allowing local reuse, reducing accidental dependence on an unknown manually-started process.

This is relevant to PocketRisu because several important invariants live at browser boundaries that are hard to prove with pure unit tests: first-run/bootstrap routing, file chooser/import paths, service-worker streamed downloads, and browser-generated download events. A narrow E2E harness can make later storage/export/import/performance changes safer without changing production behavior.
