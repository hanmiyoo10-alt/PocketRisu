## v1.13 충돌과 해소

실제 merge conflict:
- `server/node/server.cjs`
- `src/ts/globalApi.svelte.ts`
- `src/ts/process/index.svelte.ts`

서버 저장 경로:
- custom `flushPendingDbUnlocked()` / public queued `flushPendingDb()` 분리를 유지.
- v1.13 신규 archive endpoint가 storage queue 안에서 다시 public flush를 호출해 교착하는 지점을 unlocked flush로 교정.
- v1.13 remote-only auto-sweep의 DB full decode 생략 최적화를 유지하면서 queue-held asset sweep은 unlocked flush 사용.
- background DB encode 경로에서도 v1.13 archive chat 복원을 수행한 뒤 encode.
- background persist 실패도 v1.13 retry scheduler로 이어지게 함.
- snapshot restore의 새 snapshot-missing 보호와 `restoringSnapshotKey`를 유지하면서 queue 재진입은 금지.

writer/session:
- local `WriterEditGuard`와 `sendChat()` 진입 guard를 유지.
- v1.13의 `flushSaves()` / `trackCharacterForSave()` 및 저장 추적 변경은 유지.
- 기존 프로젝트 guardrail에 따라 session handoff를 자동 reload 복구로 넓히지 않음.

notification:
- 서버폰 Android notification 금지 유지.
- `/api/termux-notify`는 main-phone relay `127.0.0.1:39120`만 호출.
- client의 start/done relay 계약 유지.

Firefox 진단:
- `e28c20a6`의 `risuDiagNoV3` / lifecycle / page-pressure 계측은 fork PR에서 제외한다.
- pre-update 진단 상태는 non-Git local backup에만 보존한다.
- #2027 조사에 다시 필요하면 v1.13 배포 뒤 별도 local-only patch로 재검토하며 제품 통합 commit에 섞지 않는다.

## Termux native dependency 주의

일반 `pnpm install --frozen-lockfile`은 Android/arm64에서
`better-sqlite3@12.9.0` postinstall이 `node-gyp`을 찾지 못해 실패했다.

v1.12 live와 v1.13 target은 둘 다 `better-sqlite3@12.9.0`이며 Node/ABI도 동일하다.
후보 검증에서는:
1. `pnpm install --frozen-lockfile --ignore-scripts`로 JS 의존성을 동기화하고,
2. live와 같은 빌드의 native addon을 후보 worktree에만 복사해 서버 테스트를 수행했다.

실배포 전 exact merged target에서 이 방식을 독립 staged runtime으로 다시 검증했다. `node_modules`를 worktree 밖 staging 경로로 옮긴 뒤에도 SQLite smoke와 server suite 151/151이 통과했다.

실배포는 일반 `pnpm install`을 실행하지 않고, stopped-service 상태에서 기존 `node_modules`/`dist`를 rollback 위치로 보존한 뒤 검증된 staged `node_modules`/`dist`를 같은 filesystem에서 교체했다. native addon SHA-256은 live source와 staged copy 모두 `f9b4f7c886eb6d0d4b05b4061142cb44c1db7b996b685704f2ecb9161b184572`로 일치했다.

이 일회성 배포 경로를 일반 safe-updater 계약으로 승격하지 않는다. durable native-dependency staging/rollback 개선은 기준 레포 issue #3215에서 별도로 추적한다.
