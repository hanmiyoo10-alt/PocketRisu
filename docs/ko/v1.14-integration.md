# PocketRisu v1.14.0 Termux integration

Tracking: `hanmiyoo10-alt/-#3610`

## Scope

This integration imports official PocketRisu `v1.14.0` into the protected
Termux deployment line while preserving the server-phone contracts documented
in `custom-termux-deployment.md`.

The three Firefox commits that currently exist only on the live server checkout
are deliberately **not** part of this integration branch:

- `cf32f901` — avoid Android sound keepalive CPU kill
- `dc7ea758` — trace same-process document recreation
- `c702a1c0` — dehydrate large chat in background

They remain a local deployment overlay until their own work is ready to leave
that scope. `generic_mock_bridge.cjs` also remains intentionally untracked.

## Contract review

The merged tree retains the custom Termux deployment contracts:

- `/api/termux-notify` relays only to the main-phone listener at
  `127.0.0.1:39120` with `X-PocketRisu-Notify-Token`.
- server/client sources do not invoke Android `termux-notification` directly.
- background database persistence retains the save worker and
  `flushPendingDbUnlocked` flow.
- database patch hash caching and plugin-storage routes remain present.
- v1.14 additions such as `pendingActivations`, activated-character carry-over,
  compressed `/api/plugin-storage/all`, and classic-model resolution are
  present in the merged tree.

## Termux dependency preparation

On the current Termux host, direct `pnpm` invocation is broken because the
installed pnpm entrypoint uses `#!/usr/bin/env node` while `/usr/bin/env` does
not exist. Validation therefore invokes the same installed pnpm module through
the Termux Node binary:

```sh
node "$PREFIX/lib/node_modules/pnpm/bin/pnpm.cjs" ...
```

No host pnpm installation was modified.

The candidate dependency tree was populated with an offline frozen-lockfile
install using `--ignore-scripts`, then the already-verified live
`better_sqlite3.node` for `better-sqlite3@12.9.0` was copied into the isolated
candidate. Its SHA-256 stayed identical:

`f9b4f7c886eb6d0d4b05b4061142cb44c1db7b996b685704f2ecb9161b184572`

An in-memory SQLite smoke test passed.

### Client / shared

The Termux host runs Node `v26.4.0`. Node 26 exposes experimental webstorage in
a state where `localStorage` is unavailable unless a backing file is supplied.
That causes 83 Gemini context-cache tests to fail before assertions.

The exact same 83 failures reproduce on the pre-update v1.13 live checkout, so
they are not a v1.14 regression. Running Vitest with
`NODE_OPTIONS=--no-experimental-webstorage` restores the expected test
environment; the affected Gemini subset then passes **111 / 111**.

With that Node-26 compatibility flag, the default suite reached:

- **102 / 103 test files PASS**
- **0 failed test files**
- only `src/lib/UI/GUI/guiRendering.test.ts` does not enter test execution on
  this Termux host.

That exact GUI test behavior reproduces on the pre-update v1.13 live checkout:
it produces no test result and is terminated by an external 120-second timeout
with exit code `124`. It is therefore recorded as a host/test-harness baseline
limitation, not a v1.14 regression.

Specific v1.14 model-binding coverage passes **48 / 48**.

## Deployment gate

This commit is integration-only. Live deployment remains incomplete until all
of the following have happened:

1. the protected fork PR is merged;
2. the three local-only Firefox commits are replayed and validated on the exact
   merged deploy target;
3. full save/DB/runtime backup is taken immediately before cutover;
4. live source and runtime are changed with rollback anchors retained;
5. runit status, health, SQLite quick-check, and restart persistence are
   verified;
6. main-phone Firefox chat/generation and notification smoke is completed.

Do not mark the v1.14 work complete before those gates have evidence in
`hanmiyoo10-alt/-#3610`.
