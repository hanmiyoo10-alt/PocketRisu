Tracking: `hanmiyoo10-alt/-#3719`

## Scope

This integration imports official PocketRisu `v1.16.0` into the protected
Termux deployment line while preserving the server-phone contracts documented
in `custom-termux-deployment.md`.

The current live-only Firefox overlay is deliberately **not** part of this
integration branch:

- `ad22abf0` — avoid Android sound keepalive CPU kill
- `17dd8ed4` — trace same-process document recreation
- `3e329f47` — dehydrate large chat in background
- `62b9e310` — lazy-load inactive prompt presets
- `f48bd6e6` — cover v1.15 preset lazy reconciliation

The exact pre-integration live state is preserved on remote ref
`backup/pre-v1.16.0-live-20261023`. The intentionally untracked
`generic_mock_bridge.cjs` also remains outside this integration branch.

## Server cold-load reconciliation

The conflict-free automatic merge is not sufficient for the custom Termux
delta-save server path.

Official v1.16.0 adds a cold-load contract where chat bodies may exist in
`fullChatStore` ahead of `database.bin`. Three bounded reconciliations are
required where that contract meets the existing fork server path:

1. `retryColdPersistLater()` uses `flushPendingDbUnlocked()` while already
   running inside `storageOperationQueue`;
2. `loadDbCacheIfMissing()` uses the same unlocked flush rule because callers
   already hold the queue;
3. custom `POST /api/chat-content/:chaId/:chatIndex` calls
   `ensureChatStore()` rather than warming `dbCache` before the upstream
   cold-load carry/retry path can preserve the newly posted body.

Same-host A/B evidence on Termux Node 26:

### Automatic merge without reconciliation

- `chat-delta-sync.test.ts`: 8 / 8 PASS
- `chat-store-cold-load.test.ts`: 3 / 10 PASS, 7 FAIL
- failures include cold-load/persist contract assertions, cascading 409 import
  state, and two 30-second timeouts

### Reconciled candidate

- `chat-delta-sync.test.ts`: 8 / 8 PASS
- `chat-store-cold-load.test.ts`: 10 / 10 PASS
- combined run: 18 / 18 PASS in about 10 seconds

The reconciliation is therefore test-proven integration compatibility work,
not an unrelated behavior change.

## Termux dependency environment

Validation uses Termux Node `v26.4.0` and invokes pnpm via the installed
module entry because the ordinary wrapper uses a non-Termux `/usr/bin/env`
shebang:

```sh
node "$PREFIX/lib/node_modules/pnpm/bin/pnpm.cjs" ...
```

The integration worktree reuses the already validated v1.15.2 dependency tree
only where the v1.16 lock/package contract remains compatible. Final candidate
validation must still prove server, compatibility, default/client, static
checks, and production build on the exact integration head.

## Deployment gate

This commit is integration-only. Live deployment remains incomplete until all
of the following have evidence:

1. the fork integration PR is green and merged;
2. the five live-only Firefox commits are replayed or deliberately reconciled
   onto the exact merged v1.16 deploy target;
3. the inactive-preset lazy-hydration experiment remains separately owned by
   `hanmiyoo10-alt/-#2027`;
4. the full release-overlay candidate passes server, compatibility,
   client/default, static, and build validation;
5. fresh source, runtime, and data rollback backups are taken immediately
   before cutover;
6. database quick checks pass while the server service is down;
7. live source/runtime switch preserves rollback anchors;
8. runit status, `/api/health`, and controlled restart persistence pass;
9. main-phone Firefox chat/generation and main-phone notification smoke pass.

Safe-updater automatic deployment remains disabled. This integration commit
does not authorize live mutation by itself.
